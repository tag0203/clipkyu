# Clipkyu

macOS のメニューバーに常駐する、個人用クリップボードマネージャです。Windows の Clibor でよく使う「履歴」と、履歴とは別の FIFO / FILO 貼り付けキューを、Mac でも同じ感覚で使えるようにしたものです。

Clibor-like menu bar clipboard manager for macOS. History plus a separate FIFO/FILO paste queue. Fully local.

## 完全にローカル

- アプリはネットワークに接続しません。解析も、アップデート確認もありません。
- エンタイトルメントファイルは置いていません。ネットワーククライアント / サーバのエンタイトルメントはありません。
- 保存先は `~/Library/Application Support/Clipkyu/store.json` だけです。ディレクトリは `0700`、ファイルは `0600` です。
- パスワードマネージャなどが付ける次のペーストボード型が付いたコピーは、履歴にもキューにも入れません。
  - `org.nspasteboard.ConcealedType`
  - `org.nspasteboard.TransientType`
  - `org.nspasteboard.AutoGeneratedType`

## 履歴とキュー

| | 履歴 | キュー |
| --- | --- | --- |
| いつ増えるか | 通常 / FIFO / FILO のどれでも、ユーザーがプレーンテキストをコピーしたとき | FIFO または FILO のときだけ、同じコピーを末尾に積む |
| 並び | 新しいものが先頭 | 古いものが先頭 |
| 連続した同じ文字列 | 畳んで 1 件にする | 畳まない。同じ文字列を 2 回貼りたいときに使う |
| 上限 | 既定 50 件。メニューの「履歴の上限」か JSON の `maxHistory`（最小 1） | 上限なし |
| ⌘V で消費したとき | 追加も削除も並べ替えもしない | いま貼った項目だけを取り除き、次をクリップボードに載せる |

キューに載せるためのクリップボード書き戻しと、メニューから履歴を選んだときの書き戻しは、内部マーカー `app.clipkyu.internal-write` を付けます。監視側はこの変化を無視するので、キューを進めても履歴は増えません。

コピー順が A → B → C のとき:

- FIFO（古い順）の貼り付け順は A, B, C。コピーした直後のクリップボードは、次に貼る先頭（この例では A）に戻します。
- FILO（新しい順）の貼り付け順は C, B, A。Clibor の LIFO と同じ向きです。

通常モードに戻してもキューは残ります。メニューバーの件数は残数です（例: `通常 3`、`FIFO 3`、`FILO 0`）。FIFO / FILO に再び切り替えると、次に貼る項目をクリップボードへ載せます。起動時も、キューが残っていれば同じことをします。通常モードの起動では、すでに入っているクリップボードは読み取らず、その後の変化だけを記録します。

メニューから履歴を選ぶと、その文字列をクリップボードに戻します。履歴にもキューにも再追加しません。FIFO / FILO 中に履歴を選んだ場合、次の 1 回の ⌘V はキューを消費せず、そのあとキューの「次」をクリップボードに戻します。

キューをクリアしても履歴は変わりません。クリップボードに残っている文字列も消しません。

## 必要な権限

クリップボードの監視自体は、一般ペーストボードの `changeCount` を約 0.25 秒ごとに見るだけで、追加の権限は要りません。

FIFO / FILO の自動送りは、ほかのアプリでの ⌘V を見る必要があります。これには **アクセシビリティ** 権限が要ります。ペーストはキーを押したとき（keyDown）に行われ、Clipkyu はその瞬間の修飾キーでただの ⌘V かを覚えます。V を離したとき（keyUp）に次の項目を載せます。Command を先に離しても進みます。⌘⇧V のように別の修飾キーを先に離しても、ただの ⌘V にはしません。keyDown の時点でクリップボードを載せ替えると、貼り付けより先に中身が変わります。次のターンまで遅らせると、連打した 2 回目の ⌘V と競合して項目を飛ばすことがあります。

ペーストボードの所有者コールバックで「読まれたこと」を検知する案は採用していません。Edit メニューを開いただけで中身を読むアプリが多く、貼り付けていないのにキューが進むためです。右クリックのペーストや、メニューの「ペースト」は MVP では検知しません。

権限がまだないときは、コピーのキューへの蓄積は続きますが ⌘V では進みません。メニューに理由を出し、次を選べます。

- アクセシビリティ権限をリクエスト（システムの確認ダイアログ）
- システム設定の「プライバシーとセキュリティ › アクセシビリティ」を開く

権限は `.app` バンドルの識別子 `app.clipkyu.Clipkyu` に結び付きます。`Scripts/package-app.sh` はアドホック署名だけを付けます（Apple の証明書もネットワーク通信も使いません）。署名が変わる再ビルドのあとは、アクセシビリティの一覧から古い Clipkyu を外して、入れ直す必要があることがあります。

## ビルドして起動する

macOS 13 以降と、Swift 5.9 以降（Xcode のコマンドラインツール）が必要です。

```bash
swift test
./Scripts/package-app.sh
open dist/Clipkyu.app
```

Dock には出しません。`Info.plist` の `LSUIElement` と、プロセスの accessory 起動ポリシーの両方でメニューバー専用にしています。`swift run` でも Dock は隠しますが、権限の記憶と `LSUIElement` のために、普段は `dist/Clipkyu.app` を起動してください。

ログイン時に起動したい場合は、システム設定のログイン項目に `dist/Clipkyu.app` を追加します。終了はメニューの「終了」です。

## 使い方

1. メニューバーのクリップボードアイコンを開く。表示は `通常 N` / `FIFO N` / `FILO N`（N はキューの残数）。
2. モードを選ぶ。
3. ほかのアプリでテキストをコピーする。履歴に入り、FIFO / FILO ならキューにも積まれる。
4. 履歴の項目を選ぶと、その文字列がクリップボードに戻る。貼り付けはいつもの ⌘V。
5. FIFO / FILO では、テキストエディタなどで ⌘V するたびにキューが一つ進み、次の文字列がクリップボードに載る。キューが空になったあとの ⌘V は、最後に貼った文字列のまま。
6. 「キューをクリア」でキューだけ空にする。

## 保存ファイル

`store.json` の時刻は Unix 時間（秒）です。アプリ起動中に手で編集しても、次の保存で上書きされます。上限だけ変えるなら、アプリを終了してから `maxHistory` を編集してください。壊れたファイルは `store.json.corrupt-<uuid>` に退避し、空の状態で起動します。

## いまの範囲

- メニューバー専用（Dock アイコンなし）
- プレーンテキストの履歴。連続重複は畳む。件数の上限あり。ローカル JSON に残す
- 項目を選ぶとクリップボードへ戻し、⌘V で貼れる
- 通常 / FIFO / FILO の切り替え
- 履歴とは別のキュー。消費しても履歴は変わらない
- メニューバーにモードとキュー残数を表示
- キューのクリア
- アクセシビリティ未許可の説明と、システム設定を開く操作

## まだやらないこと

キーボードショートカット、Ctrl 二回のポップアップ、画像、スニペット / テンプレート、Undo、公証（notarization）、右クリックやメニューからのペースト検知、サンドボックス化。

既知の制限: コピーの直後（目安 0.25 秒以内）に ⌘V すると、キュー先頭へ戻す前の文字列が貼られることがあります。そのコピーは履歴とキューに残り、押した時点のキュー先頭は消しません。FIFO では、その項目はあとから改めて貼られます。

## 開発

ロジックは `Sources/ClipkyuCore` にあり、AppKit に依存しません。テストは FIFO / FILO の順序、キューと履歴の分離、連続重複、上限、秘匿型のスキップ、⌘V の判定です。

```bash
swift test
make check   # 通信コードが増えていないこと
```

Linux ではコアのテストだけがパッケージに含まれます。アプリのビルドとテストの正は macOS です。GitHub Actions（`macos-15`）が `swift test` と `.app` の組み立てを、pull request と `main` への push で実行します。サードパーティ Action はコミット SHA で固定し、`permissions: contents: read` のみ、シークレットは使いません。

このリポジトリの開発マシンが Linux の場合、macOS の ⌘V とメニューバーはそこでは実行できません。下の手順で実機確認してください。

## 手動で確認してほしいこと

1. `open dist/Clipkyu.app` で起動し、Dock にアイコンが出ないこと。メニューバーに `通常 0` が出ること。
2. テキストを 2 回コピーし、メニューの履歴が新しい順で、同じ文字列の連続コピーは 1 件のままであること。アプリを終了して起動し直し、履歴が残っていること。
3. モードを FIFO にする。アクセシビリティを許可する。A、B、C を順にコピーし、メニューのキュー先頭が「次」で、表示が `FIFO 3` であること。
4. テキストエディタで ⌘V を 3 回押し、貼られる順が A, B, C であること。キューが空になり、履歴は A, B, C のままで増減しないこと。
5. FILO で同じコピーをすると、貼られる順が C, B, A であること。
6. キューに項目がある状態で「キューをクリア」し、履歴は残ること。
7. 履歴の古い項目を選び、ほかのアプリで ⌘V するとその文字列が貼られること。FIFO 中なら、その 1 回ではキューが減らず、その後クリップボードがキューの「次」に戻ること。
8. システム設定で Clipkyu のアクセシビリティを外す。メニューに理由と「システム設定のアクセシビリティを開く」が出ること。その状態でもコピーはキューに入り、⌘V では進まないこと。
9. パスワードマネージャからコピーし、履歴に入らないこと（マーカーを付けないアプリのコピーは記録されます）。
10. `~/Library/Application Support/Clipkyu/store.json` 以外にデータが書き出されていないこと。
